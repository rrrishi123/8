gRPC is just HTTP/2 carrying a tiny framing: each message is one length-prefixed protobuf, and the call's outcome rides a trailer. unary = one message each way (CALL); server-stream = one request, many response frames (CHANNEL). why there is no live button here

A browser cannot speak raw gRPC — it needs grpc-web plus a proxy (Envoy / grpcwebproxy) to translate, because JS has no access to HTTP/2 trailers or the raw framing. So gRPC is proven in Go, where net/http speaks real HTTP/2 natively.

the mode mapping
gRPC methodwire modeshape
unaryCALLone request frame → one response frame
server-streamingCHANNELone request frame → N response frames
How this is proven: adapters/grpc stands up a real HTTP/2 server (httptest with EnableHTTP2+TLS, ALPN-negotiated h2) and drives unary (CALL) and server-stream (CHANNEL) through this exact framing — no protoc, no grpc library. The encoder on this page is a faithful JS port of that Go codec: [0x00][4-byte length][protobuf], where the protobuf for one string field is 0x0a + varint-length + UTF-8 bytes.
